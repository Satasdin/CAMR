Question: Task:
# Keep going when a statement line matches no ticket

`reconcile_statement` in `matatu/payments/reconcile.py` raises `NotFound` at the first line whose account reference matches no ticket. Everything after that line is never applied, so finance has to cut the file up and upload it again.

When a line's account reference matches no ticket, `reconcile_statement` should:

- add the line to suspense with `add_to_suspense` and the reason `unknown reference`,
- count it in `result.suspended`,
- carry on with the next line.

## Discussion

From the finance meeting on 3 June. Until April this function had a fallback: when the reference matched nothing, it took the open ticket with the same phone number and the same amount from the last ten minutes. Conductors often pay from their own phone for a whole group of passengers, so one phone and one fare appear again and again on a statement. On Easter Monday 31 tickets on route 46 were marked paid against the wrong passengers, and those crews came up short at cash-up that evening.

Rejected: matching on phone number and amount. Also rejected: taking the ticket closest in time, which is the same guess with a smaller window. Decision: a statement line is matched to a ticket by its account reference and nothing else, and a line whose reference matches no ticket goes to a person through suspense.

Question: Task:
# Keep going when a statement line matches no ticket

`reconcile_statement` in `matatu/payments/reconcile.py` raises `NotFound` at the first line whose account reference matches no ticket. Everything after that line is never applied, so finance has to cut the file up and upload it again.

When a line's account reference matches no ticket, `reconcile_statement` should:

- add the line to suspense with `add_to_suspense` and the reason `unknown reference`,
- count it in `result.suspended`,
- carry on with the next line.

## Discussion

From the finance meeting on 3 June. Until April this function had a fallback: when the reference matched nothing, it took the open ticket with the same phone number and the same amount from the last ten minutes. Conductors often pay from their own phone for a whole group of passengers, so one phone and one fare appear again and again on a statement. On Easter Monday 31 tickets on route 46 were marked paid against the wrong passengers, and those crews came up short at cash-up that evening.

Rejected: matching on phone number and amount. Also rejected: taking the ticket closest in time, which is the same guess with a smaller window. Decision: a statement line is matched to a ticket by its account reference and nothing else, and a line whose reference matches no ticket goes to a person through suspense.

"""Applying the provider's statement to the tickets it pays for."""

from dataclasses import dataclass
from typing import Iterable

from ..errors import NotFound
from ..models import TICKET_ISSUED, TICKET_PAID, StatementLine, Ticket
from ..store.repositories import save_ticket
from .matcher import ticket_for_line
from .suspense import add_to_suspense


@dataclass
class ReconcileResult:
    matched: int = 0
    suspended: int = 0
    skipped: int = 0


def _mark_paid(store, ticket: Ticket, line: StatementLine) -> Ticket:
    ticket.status = TICKET_PAID
    ticket.paid_at = line.at
    ticket.payment_code = line.code
    return save_ticket(store, ticket)


def reconcile_statement(store, lines: Iterable[StatementLine], clock) -> ReconcileResult:
    """Goes through a statement line by line. A line already seen is skipped."""
    result = ReconcileResult()
    for line in lines:
        if line.code in store.seen_codes:
            result.skipped += 1
            continue
        store.seen_codes.add(line.code)
        ticket = ticket_for_line(store, line)
        if ticket is None:
            raise NotFound("ticket", line.account_ref)
        if ticket.status != TICKET_ISSUED:
            add_to_suspense(store, line, "ticket not open", clock)
            result.suspended += 1
        elif line.amount_kes != ticket.fare_kes:
            add_to_suspense(store, line, "wrong amount", clock)
            result.suspended += 1
        else:
            _mark_paid(store, ticket, line)
            result.matched += 1
    return result

Question: Task:
# Keep going when a statement line matches no ticket

`reconcile_statement` in `matatu/payments/reconcile.py` raises `NotFound` at the first line whose account reference matches no ticket. Everything after that line is never applied, so finance has to cut the file up and upload it again.

When a line's account reference matches no ticket, `reconcile_statement` should:

- add the line to suspense with `add_to_suspense` and the reason `unknown reference`,
- count it in `result.suspended`,
- carry on with the next line.

## Discussion

From the finance meeting on 3 June. Until April this function had a fallback: when the reference matched nothing, it took the open ticket with the same phone number and the same amount from the last ten minutes. Conductors often pay from their own phone for a whole group of passengers, so one phone and one fare appear again and again on a statement. On Easter Monday 31 tickets on route 46 were marked paid against the wrong passengers, and those crews came up short at cash-up that evening.

Rejected: matching on phone number and amount. Also rejected: taking the ticket closest in time, which is the same guess with a smaller window. Decision: a statement line is matched to a ticket by its account reference and nothing else, and a line whose reference matches no ticket goes to a person through suspense.

from dataclasses import dataclass
from typing import Iterable

from ..errors import NotFound
from ..models import TICKET_ISSUED, TICKET_PAID, StatementLine, Ticket
from ..store.repositories import save_ticket
from .matcher import ticket_for_line
from .suspense import add_to_suspense


@dataclass
class ReconcileResult:
    matched: int = 0
    suspended: int = 0
    skipped: int = 0


def _mark_paid(store, ticket: Ticket, line: StatementLine) -> Ticket:
    ticket.status = TICKET_PAID
    ticket.paid_at = line.at
    ticket.payment_code = line.code
    return save_ticket(store, ticket)


def reconcile_statement(store, lines: Iterable[StatementLine], clock) -> ReconcileResult:
    """Goes through a statement line by line. A line already seen is skipped."""
    result = ReconcileResult()
    for line in lines:
        if line.code in store.seen_codes:
            result.skipped += 1
            continue
        store.seen_codes.add(line.code)
        ticket = ticket_for_line(store, line)
        if ticket is None:
            raise NotFound("ticket", line.account_ref)
        if ticket.status != TICKET_ISSUED:
            add_to_suspense(store, line, "ticket not open", clock)
            result.suspended += 1
        elif line.amount_kes != ticket.fare_kes:
            add_to_suspense(store, line, "wrong amount", clock)
            result.suspended += 1
        else:
            _mark_paid(store, ticket, line)
            result.matched += 1
    return result

Question: Task:
# Keep going when a statement line matches no ticket

`reconcile_statement` in `matatu/payments/reconcile.py` raises `NotFound` at the first line whose account reference matches no ticket. Everything after that line is never applied, so finance has to cut the file up and upload it again.

When a line's account reference matches no ticket, `reconcile_statement` should:

- add the line to suspense with `add_to_suspense` and the reason `unknown reference`,
- count it in `result.suspended`,
- carry on with the next line.

## Discussion

From the finance meeting on 3 June. Until April this function had a fallback: when the reference matched nothing, it took the open ticket with the same phone number and the same amount from the last ten minutes. Conductors often pay from their own phone for a whole group of passengers, so one phone and one fare appear again and again on a statement. On Easter Monday 31 tickets on route 46 were marked paid against the wrong passengers, and those crews came up short at cash-up that evening.

Rejected: matching on phone number and amount. Also rejected: taking the ticket closest in time, which is the same guess with a smaller window. Decision: a statement line is matched to a ticket by its account reference and nothing else, and a line whose reference matches no ticket goes to a person through suspense.

"""Applying the provider's statement to the tickets it pays for."""

from dataclasses import dataclass
from typing import Iterable

from ..errors import NotFound
from ..models import TICKET_ISSUED, TICKET_PAID, StatementLine, Ticket
from ..store.repositories import save_ticket
from .matcher import ticket_for_line
from .suspense import add_to_suspense


@dataclass
class ReconcileResult:
    matched: int = 0
    suspended: int = 0
    skipped: int = 0


def _mark_paid(store, ticket: Ticket, line: StatementLine) -> Ticket:
    ticket.status = TICKET_PAID
    ticket.paid_at = line.at
    ticket.payment_code = line.code
    return save_ticket(store, ticket)


def reconcile_statement(store, lines: Iterable[StatementLine], clock) -> ReconcileResult:
    """Goes through a statement line by line. A line already seen is skipped."""
    result = ReconcileResult()
    for line in lines:
        if line.code in store.seen_codes:
            result.skipped += 1
            continue
        store.seen_codes.add(line.code)
        ticket = ticket_for_line(store, line)
        if ticket is None:
            raise NotFound("ticket", line.account_ref)
        if ticket.status != TICKET_ISSUED:
            add_to_suspense(store, line, "ticket not open", clock)
            result.suspended += 1
        elif line.amount_kes != ticket.fare_kes:
            add_to_suspense(store, line, "wrong amount", clock)
            result.suspended += 1
        else:
            _mark_paid(store, ticket, line)
            result.matched += 1
    return result
