16: def parcel_problems(request: Dict) -> List[str]:
17:     problems = missing_fields(request, REQUIRED_PARCEL_FIELDS)
18:     if problems:
19:         return problems
20:     for key in ("origin_zone", "destination_zone"):
21:         if not is_known(request[key]):
22:             problems.append(f"{key} is not a zone we serve")
23:     weight = request["weight_kg"]
24:     if not isinstance(weight, (int, float)) or isinstance(weight, bool):
25:         problems.append("weight_kg must be a number")
26:     elif not MIN_WEIGHT_KG <= weight <= MAX_WEIGHT_KG:
27:         problems.append(f"weight_kg must be between {MIN_WEIGHT_KG} and {MAX_WEIGHT_KG}")
28:     if request.get("service", "standard") not in SERVICE_LEVELS:
29:         problems.append("service is not one we offer")
30:     return problems

35:     if problems:
36:         raise ValidationFailed(problems)

Question: Task:
# Parcel timeline

Add `courier/tracking/timeline.py` with `build_timeline(store, parcel_id)`. It returns a list of dictionaries with the keys `status`, `at` and `note`, one per tracking event for the parcel. Depots upload scans late, so events can be stored out of order. An unknown parcel raises `NotFound`, as `get_parcel` does.

Add a handler `parcel_timeline(request, context)` to `courier/api/handlers.py`. It takes `{"parcel_id": ...}` and returns `{"parcel_id": ..., "events": [...]}`, using the `handled` decorator like the other handlers.

## Discussion

Talked this through with the mobile team. Our first version returned the newest event first. The drivers' mobile app reverses the list itself before drawing it, so version 2.3 showed every delivery upside down and support took complaints for a week. The mobile team cannot change this, because old versions of the app stay on drivers' phones for about a year.

Decision: `build_timeline` always returns events oldest first. Rejected: newest first, and rejected a query option for the order, since older app versions would not send it.

# Parcel timeline

Add `courier/tracking/timeline.py` with `build_timeline(store, parcel_id)`. It returns a list of dictionaries with the keys `status`, `at` and `note`, one per tracking event for the parcel. Depots upload scans late, so events can be stored out of order. An unknown parcel raises `NotFound`, as `get_parcel` does.

Add a handler `parcel_timeline(request, context)` to `courier/api/handlers.py`. It takes `{"parcel_id": ...}` and returns `{"parcel_id": ..., "events": [...]}`, using the `handled` decorator like the other handlers.

## Discussion

Talked this through with the mobile team. Our first version returned the newest event first. The drivers' mobile app reverses the list itself before drawing it, so version 2.3 showed every delivery upside down and support took complaints for a week. The mobile team cannot change this, because old versions of the app stay on drivers' phones for about a year.

Decision: `build_timeline` always returns events oldest first. Rejected: newest first, and rejected a query option for the order, since older app versions would not send it.

def handled(function):
    """Turns expected errors into a response the web layer can send."""

    @wraps(function)

        try:
            return function(request, context)
        except CourierError as problem:
            return {"error": problem.code, "message": str(problem)}

# Parcel timeline

Add `courier/tracking/timeline.py` with `build_timeline(store, parcel_id)`. It returns a list of dictionaries with the keys `status`, `at` and `note`, one per tracking event for the parcel. Depots upload scans late, so events can be stored out of order. An unknown parcel raises `NotFound`, as `get_parcel` does.

Add a handler `parcel_timeline(request, context)` to `courier/api/handlers.py`. It takes `{"parcel_id": ...}` and returns `{"parcel_id": ..., "events": [...]}`, using the `handled` decorator like the other handlers.

## Discussion

Talked this through with the mobile team. Our first version returned the newest event first. The drivers' mobile app reverses the list itself before drawing it, so version 2.3 showed every delivery upside down and support took complaints for a week. The mobile team cannot change this, because old versions of the app stay on drivers' phones for about a year.

Decision: `build_timeline` always returns events oldest first. Rejected: newest first, and rejected a query option for the order, since older app versions would not send it.

@dataclass
class Context:
    store: object
    gateway: object
    clock: object
    sender: object


def handled(function):
    """Turns expected errors into a response the web layer can send."""

    @wraps(function)
    def wrapper(request, context):
        try:
            return function(request, context)
        except CourierError as problem:
            return {"error": problem.code, "message": str(problem)}

    return wrapper


def _parcel_from(request, identifier, now) -> Parcel:

                  destination_zone=request["destination_zone"], weight_kg=request["weight_kg"],
                  service=request.get("service", "standard"), fragile=bool(request.get("fragile")),
                  insured_value_cents=int(request.get("insured_value_cents", 0)), created_at=now)

def quote(request, context):
    check_parcel(request)
    customer = get_customer(context.store, request["customer_id"])
