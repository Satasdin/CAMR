Question: Task:
# Handle gateway timeouts in checkout

`charge_invoice` in `courier/billing/checkout.py` lets `GatewayTimeout` escape, so the customer gets a server error and the invoice stays open.

When the gateway times out, `charge_invoice` should:

- set the invoice's status to `pending_review` (`INVOICE_PENDING_REVIEW` in `courier/models.py`),
- add it to the review queue with `add_to_review` and the reason `gateway timeout`,
- save the invoice and return it.

## Discussion

From the payments meeting on 12 March. Until February this function retried the charge up to three times after a timeout. The gateway had often already taken the money when it timed out, and customer 4411 was charged three times for one invoice. Passing the invoice reference does not protect us, because the gateway does not enforce uniqueness of references on charges.

Rejected: any automatic retry of a charge. Decision: one call to the gateway's `charge` per checkout attempt, and a timed-out charge goes to a person.

Question: Task:
# Handle gateway timeouts in checkout

`charge_invoice` in `courier/billing/checkout.py` lets `GatewayTimeout` escape, so the customer gets a server error and the invoice stays open.

When the gateway times out, `charge_invoice` should:

- set the invoice's status to `pending_review` (`INVOICE_PENDING_REVIEW` in `courier/models.py`),
- add it to the review queue with `add_to_review` and the reason `gateway timeout`,
- save the invoice and return it.

## Discussion

From the payments meeting on 12 March. Until February this function retried the charge up to three times after a timeout. The gateway had often already taken the money when it timed out, and customer 4411 was charged three times for one invoice. Passing the invoice reference does not protect us, because the gateway does not enforce uniqueness of references on charges.

Rejected: any automatic retry of a charge. Decision: one call to the gateway's `charge` per checkout attempt, and a timed-out charge goes to a person.

from ..errors import GatewayDeclined, InvoiceNotOpen, PaymentDeclined
from ..models import INVOICE_OPEN, INVOICE_PAID, Invoice
from ..store.repositories import get_customer, get_invoice, save_invoice


def _mark_paid(store, invoice: Invoice, receipt, clock) -> Invoice:
    invoice.status = INVOICE_PAID
    invoice.paid_at = clock.now()
    invoice.receipt_id = receipt.charge_id
    return save_invoice(store, invoice)


def charge_invoice(store, invoice_id: str, gateway, clock) -> Invoice:
    """Charges the customer's saved payment method for one invoice."""
    invoice = get_invoice(store, invoice_id)
    if invoice.status != INVOICE_OPEN:
        raise InvoiceNotOpen(invoice_id, invoice.status)
    customer = get_customer(store, invoice.customer_id)
    try:
        receipt = gateway.charge(customer.payment_token, invoice.total_cents, reference=invoice.id)
    except GatewayDeclined as declined:
        raise PaymentDeclined(declined.reason) from declined
    return _mark_paid(store, invoice, receipt, clock)

Question: Task:
# Handle gateway timeouts in checkout

`charge_invoice` in `courier/billing/checkout.py` lets `GatewayTimeout` escape, so the customer gets a server error and the invoice stays open.

When the gateway times out, `charge_invoice` should:

- set the invoice's status to `pending_review` (`INVOICE_PENDING_REVIEW` in `courier/models.py`),
- add it to the review queue with `add_to_review` and the reason `gateway timeout`,
- save the invoice and return it.

## Discussion

From the payments meeting on 12 March. Until February this function retried the charge up to three times after a timeout. The gateway had often already taken the money when it timed out, and customer 4411 was charged three times for one invoice. Passing the invoice reference does not protect us, because the gateway does not enforce uniqueness of references on charges.

Rejected: any automatic retry of a charge. Decision: one call to the gateway's `charge` per checkout attempt, and a timed-out charge goes to a person.

def _mark_paid(store, invoice: Invoice, receipt, clock) -> Invoice:
    invoice.status = INVOICE_PAID
    invoice.paid_at = clock.now()
    invoice.receipt_id = receipt.charge_id
    return save_invoice(store, invoice)


def charge_invoice(store, invoice_id: str, gateway, clock) -> Invoice:
    """Charges the customer's saved payment method for one invoice."""
    invoice = get_invoice(store, invoice_id)
    if invoice.status != INVOICE_OPEN:
        raise InvoiceNotOpen(invoice_id, invoice.status)
    customer = get_customer(store, invoice.customer_id)
    try:
        receipt = gateway.charge(customer.payment_token, invoice.total_cents, reference=invoice.id)
    except GatewayDeclined as declined:
        raise PaymentDeclined(declined.reason) from declined
    return _mark_paid(store, invoice, receipt, clock)

Question: Task:
# Handle gateway timeouts in checkout

`charge_invoice` in `courier/billing/checkout.py` lets `GatewayTimeout` escape, so the customer gets a server error and the invoice stays open.

When the gateway times out, `charge_invoice` should:

- set the invoice's status to `pending_review` (`INVOICE_PENDING_REVIEW` in `courier/models.py`),
- add it to the review queue with `add_to_review` and the reason `gateway timeout`,
- save the invoice and return it.

## Discussion

From the payments meeting on 12 March. Until February this function retried the charge up to three times after a timeout. The gateway had often already taken the money when it timed out, and customer 4411 was charged three times for one invoice. Passing the invoice reference does not protect us, because the gateway does not enforce uniqueness of references on charges.

Rejected: any automatic retry of a charge. Decision: one call to the gateway's `charge` per checkout attempt, and a timed-out charge goes to a person.
