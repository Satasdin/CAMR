## Size

## Skeleton (use these headings)
- **Front:** Declaration and Approval (template), Acknowledgment (five lines), Abstract (230 to 250 words, two or three paragraphs: problem, what was built, data and method, ONE headline number, implication; then four or five keywords), Table of Contents, List of Figures, List of Tables, List of Equations, List of Abbreviations.
- **Ch 1 Introduction:** 1.1 Background Information; 1.2 Problem Statement; 1.3 Research Objectives (1.3.1 General Objective, 1.3.2 Specific Objectives); 1.4 Research Questions; 1.5 Justification; 1.6 Scope; 1.7 Limitations and Delimitations (1.7.1, 1.7.2).
- **Ch 2 Literature Review:** 2.1 Introduction; 2.2 Current State of <the field> (2.2.1 overview … last subsection Key Challenges); 2.3 Related Works (one subsection per system); 2.4 Gaps in Related Works; 2.5 Conceptual Framework (one figure).
- **Ch 3 Methodology:** 3.1 Introduction; 3.2 Research Paradigm (3.2.1 Data Acquisition, 3.2.2 Data Processing, 3.2.3 Model Training, 3.2.4 Model Validation and Testing); 3.3 System Development Methodology (3.3.1 Justification); 3.4 Methodology Diagram (one figure, then one short subsection per stage); 3.5 System Analysis Diagrams (one two-to-three-line subsection naming each diagram and what it will show: Use Case, Sequence, Activity, Class); 3.6 System Design Diagrams (Database Schema, Wireframes, System Architecture); 3.7 Deliverables (one short subsection each); 3.8 Tools and Techniques (one short subsection each).
- **Ch 4 System Analysis and Design:** 4.1 Introduction; 4.2 System Requirements (4.2.1 Functional, 4.2.2 Non-functional); 4.3 System Analysis Diagrams (one subsection per diagram); 4.4 System Design Diagrams (Database Schema, Wireframes, System Architecture). About 10 figures; each diagram gets a two-to-four-line paragraph before it and nothing after; 3 to 4 screen wireframes.
- **Ch 5 System Implementation and Testing:** 5.1 Introduction; 5.2 Implementation Environment (5.2.1 Hardware Specifications, 5.2.2 Software Specifications, two small tables: Component | Description and Justification; Software | Version | Role); 5.3 Description of the Dataset; 5.4 System Implementation (by module, screenshots); 5.5 evaluation (components, metrics as captioned equations, results with charts); 5.6 System Testing (ONE table: Test Case ID | Module | Description | Test Data | Expected Result | Actual Result | Pass/Fail; 9 to 12 end-user-worded cases); 5.7 Results and Discussion (about one page of prose with the numbers, closing with a paragraph saying which objectives were met); 5.8 GitHub Documentation (repository URL, folder structure, branch and tag workflow, a screenshot).
- **Appendix:** Gantt chart, app screenshots, an extra chart, similarity report. Images, little text.

## Style that worked
- Plain past tense. Short paragraphs. One headline number repeated in the abstract and Chapter 5.
- Figures carry the report: real screenshots, real charts, UML. 4 to 6 tables in Chapter 5, not 18. No typeset code listings; code or console output appears only as a screenshot figure.
- Every figure and table is introduced by number in the sentence before it. Figure caption below and centred; table caption above.
- Weaknesses are stated in 1.7 and in one limitations paragraph, not after every sentence.
- Related works in the references have NO images; ours keeps a real image for each (our supervisor's panel liked that in the proposal).
